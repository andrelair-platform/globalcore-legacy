# GlobalCore — legacy insurance core (practice System of Record)

> A **deliberately-legacy** insurance policy core, built to practice the enterprise pattern:
> **keep a rigid old core running, build modern features *around* it.** Java 8 / Spring / **SOAP** /
> **nightly batch** / one shared PostgreSQL schema. Modelled on IBM's **GenApp** insurance data model.
>
> **The iron rule: GlobalCore is FROZEN.** You do **not** add modern capabilities inside it — you wrap
> it (Anti-Corruption Layer → strangler-fig). Plan: `ktayl-integration/docs/legacy-wrapper-initiative-spec.md`.

## What's deliberately "legacy" here (and why)
| Trait | How it shows up | Why it matters |
|---|---|---|
| **SOAP/XML only** | the only API is `/ws` (WSDL at `/ws/policy.wsdl`) — no REST, no JSON | forces a wrapper/translator |
| **Batch, not real-time** | `createPolicy` inserts status `P` (pending); a policy is **official only after the nightly batch** flips it to `A` | you must design around async issuance |
| **Business logic in the DB** | the rating engine + renewal generation are **PostgreSQL stored procedures** | rules aren't in the app layer — classic legacy |
| **Cryptic shared schema** | one `gcore` schema, ≤8-char columns (`POLNO`, `PREMAMT`, `EFFDT`), codes not enums (`LOBCD` MAR/PRO/AVI, `STATCD` P/A/L/C) | the ugly representation an ACL has to hide |
| **Runs outside k8s** | plain Docker container | legacy isn't cloud-native; the modern platform reaches *out* to it |

## Domain (v0 = Policy)
Customers + brokers + policies with **effective-dated versions** (`GC_POLVER`) + **endorsements**
(`GC_ENDMT`) + multi-currency. Renewals are generated by the batch into new versions.

## Run it (no local JDK needed — builds in Docker)
```bash
docker compose up --build
# WSDL:
curl -s http://localhost:8080/ws/policy.wsdl | head
```

### Read a policy (SOAP)
```bash
curl -s http://localhost:8080/ws -H 'Content-Type: text/xml' -d '
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/" xmlns:p="http://globalcorp.com/gcore/policy">
  <soap:Body><p:GetPolicyRequest><p:polNo>POL0000001</p:polNo></p:GetPolicyRequest></soap:Body>
</soap:Envelope>'
```
Returns the ugly legacy XML (codes, `verNo`, endorsements) that a modern layer must translate.

### Create a policy (lands PENDING until the batch runs)
```bash
curl -s http://localhost:8080/ws -H 'Content-Type: text/xml' -d '
<soap:Envelope xmlns:soap="http://schemas.xmlsoap.org/soap/envelope/" xmlns:p="http://globalcorp.com/gcore/policy">
  <soap:Body>
    <p:CreatePolicyRequest>
      <p:custNo>CUST0001</p:custNo><p:brkCd>BRK00001</p:brkCd><p:lobCd>MAR</p:lobCd>
      <p:currCd>EUR</p:currCd><p:effDt>2027-01-01</p:effDt><p:expDt>2027-12-31</p:expDt>
      <p:sumIns>75000000</p:sumIns>
    </p:CreatePolicyRequest>
  </soap:Body>
</soap:Envelope>'
```
It returns `statCd = P`. Wait for the batch (every 2 min; watch the app logs) — the new policy and
the expiring seed policy `POL0000002` get processed (activated / renewed).

## What you build next (NOT in this repo — that's the whole point)
An **Anti-Corruption Layer** that turns this SOAP into clean JSON, a modern **underwriting workbench**
that reads a policy *through* the ACL, and document-AI ingestion — see the initiative spec.
